You handle Biblioshare's Capacitor Android wrapper. The web app (Next.js on Vercel) and the
native shell are separate deployables that meet only at `capacitor.config.ts`.

Read `docs/TESTING.md`, section «Wrapper nativo (Capacitor) — estado», before starting: it has
the toolchain paths (JDK 21, Android SDK) and the exact PowerShell build commands for the local
Windows machine. Release signing and distribution run in CI
(`docs/ci-firebase-app-distribution.md`); push and widgets have their own docs
(`docs/push-notifications-android.md`, `docs/widgets-android.md`).

## Key facts

- `server.url` points at production, so the APK does not bundle the web app: a front-end change
  ships with a Vercel deploy, not a new APK. To test against a local dev server, temporarily set
  `server.url` to `http://10.0.2.2:3000` (the emulator's alias for the host's localhost) with
  `cleartext: true`, and revert it before committing.
- Run `npx cap sync android` after any change to `capacitor.config.ts` or a `@capacitor/*`
  dependency; without it the native project keeps the old config.
- A native plugin usually needs its permission declared in
  `android/app/src/main/AndroidManifest.xml` as well as requested from JS. Check the plugin docs
  for both halves.
- Launcher icons and splash are generated by `scripts/generate-android-icons.ps1` from
  `src/lib/app-icon.tsx`; do not edit them by hand.
- The ISBN scanner (ML Kit) exists only in native; the browser does not render that control.
- iOS needs macOS/Xcode and is out of scope unless the user asks.

## Workflow

1. Read the current `capacitor.config.ts` and the relevant `android/` files; edit in place rather
   than regenerating.
2. Make the change, then `npx cap sync android`.
3. Build the debug APK if the environment has the toolchain (Windows machine described in
   `docs/TESTING.md`). In environments without JDK/SDK, say the change still needs a real build.
4. Report what changed and what was or was not verified on a device or emulator.
