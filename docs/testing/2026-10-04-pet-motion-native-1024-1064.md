## Preparaciones fallidas conservadas

1. `run01`: Next/Turbopack detectó el proxy del árbol padre y los aliases
   absolutos de Windows se resolvieron como rutas relativas inválidas. No se
   ejecutó el gate de producto. Se cerraron sus procesos propios.
2. `run02`: el montaje con copias exactas aisló las fuentes, pero Turbopack
   rechazó la unión de `node_modules` fuera de su raíz y terminó. Chromium
   registró `ERR_CONNECTION_REFUSED`. Su captura blanca fue inspeccionada;
   no acredita render del componente. Se conserva el log de pánico.
3. `run03`: Next/Webpack heredó los plugins PostCSS del padre, incompatibles
   con `experimental.useLightningcss`. GET `/` quedó sin respuesta y la
   navegación agotó 60 s; la captura no llegó a producirse. Browser y Next
   propios se cerraron. El aislamiento PostCSS se preparó en una ruta nueva.

`run04` utiliza PostCSS privado con plugins vacíos, para que Lightning CSS
compile el módulo. Las cinco fuentes TSX/CSS/manifiesto/metadatos/clases y
